# VOIDEX Launcher

A lightweight, customizable Minecraft Java launcher for Windows, built with Python and PySide6.

## Current preview features

- Dark cosmic UI with Overview, Versions, a working Modrinth mod browser, Accounts, Settings and Console pages.
- On-demand, size-bounded retrieval of Mojang's official version manifest. VOIDEX validates the catalog schema, version IDs, metadata URLs and SHA-1 values before displaying entries; redirects remain on Mojang's official HTTPS metadata hosts. The catalog supports searching and filtering releases, snapshots, old beta and old alpha entries.
- On-demand inspection of a selected version's official Mojang metadata, including Java major-version requirement, client JAR size/checksum, asset index and library count. Version JSON responses are size-bounded, parsed as JSON objects and fetched only through Mojang's official HTTPS metadata hosts (`piston-meta.mojang.com` and the legacy `launchermeta.mojang.com` host used by older releases); redirects are restricted to those hosts. Client download hosts are separately restricted to Mojang HTTPS hosts.
- Optional download and caching of the selected version JSON, verified against the SHA-1 recorded in the official version manifest. The JSON is parsed before atomic replacement and cached under the version-specific VOIDEX directory.
- Platform-aware resolution of Mojang library artifacts and native classifiers from version JSON, including ordered allow/disallow rules and feature flags. Resolved paths, HTTPS URLs, SHA-1 values and sizes are validated before a download stage is allowed.
- Core native JAR extraction helper with ZIP path traversal checks, symlink rejection, META-INF filtering, duplicate-path detection, bounded entry/file/total sizes, destination containment checks, and atomic per-file writes. The Versions page now has a **Prepare natives** action that reuses verified native JAR downloads and extracts them in a background worker to `.voidex/versions/<version>/natives`. A successful extraction pass prunes stale files from the internal natives folder. Launch preflight rechecks each native archive's size and SHA-1, compares every extracted file byte-for-byte with its archive, and rejects missing, modified, symlinked or unexpected native files. Versions with no native classifiers can use an empty native directory or the validated `.voidex-ready` marker.
- Asset-index object resolution maps each logical asset to its content-addressed SHA-1 path and the fixed Mojang asset host. The Versions page now has an **Install assets** action: it verifies/caches the version JSON, downloads and verifies its asset index, then downloads all required object files in a background worker to `.voidex/assets/objects`; the index is cached under `.voidex/assets/indexes`. The install and launch pipelines also reconstruct legacy `virtual: true` indexes under `.voidex/assets/virtual/<index-id>` and `map_to_resources: true` indexes under the active instance's `resources` folder. Copies are streamed, SHA-1 checked, atomically replaced and protected against unsafe paths and symlinks; valid reconstructed files are reused. If Mojang metadata omits `assetIndex`, VOIDEX does not invent an index or object list: it prepares an empty `.voidex/assets/virtual/legacy` directory and continues with the legacy game-assets path. Such versions can still fail if the client expects external resources that are not described by its metadata.
- Core library artifact downloader for resolved Maven entries: same-host HTTPS redirects only, cache verification, streamed size/SHA-1 checks, atomic replacement and temporary-file cleanup. Native classifier JARs are downloaded but not extracted. A sequential batch helper downloads multiple resolved artifacts and reports aggregate byte progress; verified cache entries are reused and conflicting destination paths are rejected before network access. The Versions page now has an **Install libraries** action: it first caches the selected version JSON with manifest SHA-1 verification, resolves Windows x64 library artifacts, then downloads them sequentially in a background worker to `.voidex/libraries`.
- Mojang Log4j2 client configuration is downloaded on demand into `.voidex/assets/log_configs`, restricted to official Mojang HTTPS hosts, bounded to 4 MiB, and verified against the version JSON's exact size and SHA-1 before atomic replacement. The launch plan adds the metadata-provided `-Dlog4j.configurationFile` JVM argument only after rechecking the cached file; an absent or modified config blocks launch rather than silently using an unverified file.
- One-button **Install selected version** pipeline: verifies and caches version JSON and client JAR, resolves and downloads Windows x64 libraries, safely extracts native archives and prunes stale native files, downloads the asset index and every referenced asset object when an index is published (otherwise prepares an empty legacy assets directory without fabricating objects), downloads and verifies the version's Log4j2 client config, verifies the complete available asset cache, reconstructs any legacy virtual/resource layout, and creates a per-version game directory. All network and extraction work runs in a background thread with stage/progress reporting; existing verified cache files are reused.
- Optional standalone download of the selected client JAR, with streamed progress, byte-count and SHA-1 verification, temporary-file cleanup and atomic replacement. A previously verified cached file is reused.
- Local Minecraft-compatible offline UUID generation from a player nickname.
- Java discovery from JAVA_HOME, PATH and common Windows JDK vendor folders. Inspecting a Minecraft version automatically checks the configured or discovered runtime against its required Java major. Older Mojang version JSON files without a `javaVersion` field use the Java 8 baseline; malformed explicit Java requirements are rejected.
- Explicit **Install required Java** action in Settings downloads the matching Windows x64 Eclipse Temurin JDK from the official Adoptium API, checks the published SHA-256 and byte size, safely extracts the ZIP with traversal/link/resource limits, runs `java.exe -version`, and saves the verified runtime path under `.voidex/runtimes`. It never downloads Java without the user's click. The requested Java major is validated before any runtime directory is created or cleaned, so malformed values cannot influence filesystem paths.
- Modrinth browser: search real mod projects for a concrete Minecraft version and Fabric / Forge / NeoForge / Quilt filter, fetch a compatible project version, and install its primary JAR into `.voidex/instances/<version>/mods`. Downloads are restricted to the official Modrinth CDN and verified against published SHA-1 or SHA-512, size-checked, written to a temporary file, and atomically installed. Search and installation run in background workers.
- A tested launch-plan builder that checks Java compatibility, required library/client files, builds a platform-specific classpath without native classifier JARs, applies Mojang OS/feature rules, expands modern or legacy game arguments, and returns a shell-free argv/cwd plan. Account credentials must be explicitly supplied; the planner does not fabricate online sessions.
- Live Minecraft stdout/stderr handling uses incremental UTF-8 decoding, so characters split across process read chunks are preserved and partial final lines are flushed. Unterminated output lines are capped at 64 KiB and marked as truncated, preventing malformed or unusually large process output from growing the pending log buffer without bound. Each launch writes a unique UTF-8 session log under `.voidex/logs`; logs are created exclusively, version IDs are filename-validated, and each session log is capped at 16 MiB. Closing VOIDEX while background QThreads are active is deferred with a clear message so workers are not destroyed mid-task. If Minecraft is running, the user is asked to stop it; VOIDEX requests graceful termination, force-stops after 3 seconds if necessary, flushes the final output and closes the session log before the window exits. A failed Java process start also clears the stale process reference and finalizes the log.
- Low-end, Balanced and High-end starting presets, editable RAM allocation, rendering profile and JVM arguments.
- Settings and the selected version are persisted with Qt settings.
- Named instances have separate `resourcepacks` and `shaderpacks` folders. The Overview page opens the folders for the active instance; the default profile keeps using its version-scoped game folder, and symbolic-link redirection is rejected.
- No permanent animation timers, polling loops, or background network requests. The Mojang manifest is requested only when the Versions page is opened or Refresh is pressed.

## Not implemented yet

This is an active preview, not a finished launcher. The following are not connected yet:

- Very old releases whose Mojang version metadata does not provide a downloadable asset index are still unsupported. When an asset index is present, installation and launch now reconstruct its `virtual` or `map_to_resources` layout from the verified object cache. One-button installation still targets Windows x64 library resolution. The launch preflight re-verifies the cached version JSON against the selected Mojang manifest SHA-1 and version ID on every launch, rejects symbolic-link version JSON and asset-index files, verifies the client JAR, library hashes, asset index, all asset objects, native archive hashes and byte-for-byte extracted native contents, and Java major, then reconstructs legacy assets before starting Java. Missing, modified, symlinked or stale native files block launch. Offline profiles can launch with a local nickname; online account providers remain blocked until their authentication flows are implemented.
- Ely.by and Microsoft authentication.
- Online skin lookup, skin upload and 3D skin preview.
- CurseForge archive import remains pending. Named instances on the Overview page can be created, selected, renamed and removed. Each profile launches into its isolated game directory, and Modrinth mods can be installed/listed/removed inside that profile. Each named profile also stores its own installed Fabric/Forge/NeoForge/Quilt launch-profile ID; launch selects only that profile's loader, while vanilla profiles cannot inherit another profile's loader. A Modrinth modpack import binds its validated generated loader profile to the target instance; if profile metadata cannot be updated, VOIDEX shows a warning and blocks unsafe cross-instance loader reuse. Selecting a named profile pins the version picker and launch preflight to that profile's Minecraft version; selecting a different catalog version is blocked until another instance is selected. Shared verified libraries and assets remain in the launcher cache. Profile IDs/names/versions/loaders are validated, profiles are listed deterministically, renaming atomically updates metadata without moving game files, and removing a profile entry preserves its game data by default. Modrinth .mrpack import can target the selected named profile when its Minecraft version matches; after a successful import, the profile's recorded loader (Vanilla/Fabric/Forge/NeoForge/Quilt) is synchronized atomically, with a visible warning if metadata could not be updated. Fabric, Forge, NeoForge and Quilt can be installed through their official installers and their generated launch profiles are merged into Mojang metadata when the selected Minecraft version matches. Added loader libraries must already exist locally and pass path, trusted-repository, size and checksum checks.
- Signed Windows installer and portable package.

The launch planner also supports the legacy `${auth_session}` placeholder used by older Minecraft metadata. It expands to `token:<access token>:<UUID without hyphens>`, while modern versions continue using separate authentication placeholders. Legacy argument strings are tokenized with Mojang-style quote handling on Windows too, so quoted paths and values containing spaces are passed as single arguments without literal quote characters.

The Launch button performs a background preflight and starts a real Java process only when required files pass integrity checks. Preflight reuses or downloads the official version's Log4j2 client configuration, verifies its SHA-1 and size, and passes its exact path to Java using the Mojang-specified JVM argument. For legacy indexes, preflight reconstructs the required `assets/virtual/<index-id>` or instance `resources` tree and supplies the legacy `${game_assets}` argument placeholder. Minecraft stdout/stderr appear live in Console and are also persisted per session under `.voidex/logs` (maximum 16 MiB per log). It currently supports explicit offline nickname sessions only; Ely.by and Microsoft authentication are not fabricated or bypassed. Use **Install selected version** on the Versions page to prepare the client JAR, libraries, assets and natives in one background operation. If a compatible Java runtime is missing, inspect the version and use **Install required Java** in Settings; the matching Temurin runtime is then installed and validated locally. In the Mods page, select a concrete Minecraft version and loader to search and install compatible Modrinth JARs. Fabric builds can be loaded from Fabric Meta and installed with the official Fabric CLI installer; VOIDEX verifies the installer JAR against its Maven SHA-1 sidecar, validates the generated profile, and merges its libraries and launch arguments into the Mojang profile at launch. The installed-mod list shows JAR filenames and sizes, and removal requires confirmation; symbolic links and paths outside the instance mods folder are rejected. Forge build discovery and official installer execution are available from the Mods page. Installer JARs are fetched from the Forge Maven host, checked against the published SHA-1 sidecar, and the generated client profile is validated. When the selected Minecraft version matches the installed Forge profile, VOIDEX merges its main class, launch arguments and Maven libraries into the launch plan; missing or untrusted libraries block launch. NeoForge catalog lookup, verified client installer execution, and launch-profile merging are available. VOIDEX validates the generated profile, merges its launch arguments and main class, and requires every added Maven library to exist locally with matching size/checksum metadata. Quilt loader builds can be discovered from the official Quilt Meta API and installed with the official Quilt installer. Its profile, main class, launch arguments and local Maven libraries are validated and merged during launch. Modrinth .mrpack archives can be imported into the selected named profile when its Minecraft version matches (or into the default version-scoped folder); client files and overrides are staged, path-checked and verified before import, and supported loader profiles are installed through their official installer.

## JVM argument safety

The RAM selector owns the launcher's initial and maximum heap settings. Custom JVM flags remain available for tuning, but VOIDEX rejects flags that would replace its managed heap size, classpath, native-library path, verified Log4j2 configuration, or Java launch mode. This prevents duplicate options from silently overriding the selected RAM or verified launch files. The Settings field groups quoted values containing spaces while preserving Windows backslashes, so a value such as `-Duser.home=C:\Users\Player` is not silently changed during tokenization.
## Requirements

- Python 3.11+
- Windows 10/11
- Internet connection for the official Mojang version catalog

## Development

```powershell
py -m venv .venv
.venv\\Scripts\\Activate.ps1
pip install -r requirements.txt
python main.py

# Run core validation and library-resolution tests
python -m unittest discover -s tests -v
```

## Build a Windows executable

A Windows x64 build is produced automatically by GitHub Actions after every push to `main`, and can also be started manually from the **Actions → Build Windows executable** page. The workflow runs the unit tests, packages the PySide6 application with PyInstaller in one-file/windowed mode, and uploads `VOIDEX.exe` as the `VOIDEX-Windows-x64` artifact for 14 days.

For a local build on Windows:

```powershell
py -m pip install -r requirements.txt pyinstaller
py -m PyInstaller --noconfirm --clean --onefile --windowed --name VOIDEX --collect-all PySide6 --hidden-import shiboken6 main.py
```

The local executable is written to `dist\\VOIDEX.exe`. The GitHub Actions artifact is a build output, not a signed installer; code signing and a dedicated installer remain future work.

## Performance note

The interface avoids continuous animation and idle polling to keep background overhead low. Actual CPU/RAM usage depends on Windows, Qt, drivers, display scaling and other running software; a fixed 2–5% idle usage cannot be guaranteed.
